Replace it with a version that wraps `AlertDialogPrimitive.Close` — mirroring the pattern used by `AlertDialogCancel`:

```tsx
function AlertDialogAction({
  className,
  variant = "default",
  size = "default",
  ...props
}: AlertDialogPrimitive.Close.Props &
  Pick<React.ComponentProps<typeof Button>, "variant" | "size">) {
  return (
    <AlertDialogPrimitive.Close
      data-slot="alert-dialog-action"
      className={cn(className)}
      render={<Button variant={variant} size={size} />}
      {...props}
    />
  )
}
```

**Why this works:** `AlertDialogPrimitive.Close` is the @base-ui/react component that hooks into the AlertDialog context and closes the popup when clicked. Using `render={<Button/>}` (the render-prop pattern) delegates visual rendering to the Button component while Close handles the dismiss behavior. The `onClick` prop forwarded via `...props` will still fire (the handler runs before the dialog closes) — so `handleConfirm`, `handleIngest`, and `handleRemove` in callers all continue to work.

**Callers that benefit (all fixed automatically by this single change):**
- `src/components/gate/GateDecisionSelector.tsx` — `AlertDialogAction onClick={handleConfirm}` — gate decisions now auto-close
- `src/components/intake/SiIntakeCard.tsx` — `AlertDialogAction onClick={handleIngest}` and `onClick={handleIngestRevised}` — ingest confirmations now auto-close
- `src/components/settings/LlmKeyConfigCard.tsx` — `AlertDialogAction onClick={handleRemove}` — key removal now auto-closes
